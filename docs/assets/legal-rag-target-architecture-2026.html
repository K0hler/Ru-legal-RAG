Legal RAG как система юридических доказательств

Решение: сначала версионированный корпус, точный retrieval и проверяемые evidence handles; агент появляется только поверх этого контура. `LAW_Data` остаётся внешним read-only источником.

1. Целевая архитектура

Канонические юридические сущности отделены от перестраиваемых поисковых проекций. Приложение не получает прямой доступ к базе, индексам или файловой системе.

2. Runtime-пайплайн запроса

Дата, юрисдикция, статус источника и ACL ограничивают множество кандидатов до любого ранжирования. Финальный ответ выпускается только после двух независимых проверок.

Делать сейчас

`Act → Edition → Provision`, provenance, review gate, exact lookup, temporal filters, русский gold set и FTS baseline.

Проверять экспериментом

Dense retrieval, RRF, reranker, metadata injection, bounded reference expansion и conditional decomposition.

Отложить

GraphRAG, multi-agent topology, отдельные search engines и локальная большая answer-модель — пока benchmark не покажет bottleneck.

Целевое состояние, а не описание уже развёрнутой системы. Рекомендуемый стек: Python · FastAPI · PostgreSQL/pgvector · React · LangGraph при доказанной необходимости.
