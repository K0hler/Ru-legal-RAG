# Исправление запуска после проверки модели в Windows

**Дата:** 04.11.2026. **Статус:** исправлено и проверено в штатной `.venv`.

## Причина

`os.execvp` в Windows передаёт аргументы без необходимого экранирования.
Путь `H:\AI_AGENT\Legal RAG\.venv\Scripts\python.exe` разбивался на части:
Python пытался открыть ошибочный путь, программа-маркер не запускалась,
а внешний процесс возвращал код `0`. Ошибка возникала после успешной проверки
весов; проверка целостности модели не была причиной.

Минимальная проверка отделила три предположения:

- При пути интерпретатора без пробелов команда запускалась, но аргумент
  `argument with spaces` превращался в три аргумента. Проблема шире `.venv`.
- Кавычки только вокруг `argv[0]` исправляли путь программы, но не аргументы.
- Ожидание ещё одной секунды не создавало файл: это не гонка проверки файла.
- `subprocess.call` со списком аргументов сохранял путь и аргументы в обоих
  окружениях; отдельная проверка подтверждает передачу кода завершения `7`.

## Изменение

После проверки всех файлов модели Windows запускает команду через
`subprocess.call(sys.argv[4:])` и возвращает её код завершения.
Linux продолжает использовать `os.execvp`; PID сохраняется.
Ручное добавление кавычек и shell не используются.

Регрессионный тест запускает настоящий проверяющий скрипт и программу с
пробелами в пути. Он проверяет аргументы с пробелами, кириллицей, кавычкой,
пустую строку и завершающий обратный слеш, а также коды `0` и `7`.
До исправления: `3 failed, 4 passed`; после исправления обе среды проходят 7/7.
Проверки повреждённых, отсутствующих и лишних весов сохранены.
