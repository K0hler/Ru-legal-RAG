# М1-04А: корпус официальных деревьев для второго слоя (JSON + HTML), v1

Дата: 25.10.2026. Статус: **набор данных для разработки второго слоя** («строки → дерево владельцев»).
Это не партия проверочного пула и не изменение протокола оценки. Предпосылка — [пилот JSON против Codex](M1_04A_JSON_CODEX_PILOT_2026-10-24.md).

## Что в корпусе

`document_content` (официальное дерево: узлы с `unit`, `caption`, `lvl` и диапазоном абзацев `np…npe`),
`documenttext` и извлечённый из него `document.html`, а также `source.json`: редакция `rdk`, хеши, признаки.

## Как отобрано

Скрипт [`acquire_m1_04a_json_corpus.py`](../../../assets/acquire_m1_04a_json_corpus.py), фазы с файлами,
которые пишутся один раз, seed 20261025, пауза между запросами ≥ 1,1 с:

1. **Кандидаты:** по 3 случайные страницы поиска IPS (по 200 актов) для каждого вида и органа.
2. **Скрининг:** карточка и дерево для перемешанных кандидатов. Раунд 2 продолжил тот же порядок,
   пока в группе не набралось вдвое больше актов с деревом, чем квота. Всего проверено 737 актов.
3. **Отбор:** внутри квоты группы жадно берётся акт, который добавляет больше всего ещё не покрытых признаков
   (единицы, пары «родитель → ребёнок», флаги, глубина, размер, десятилетие); ничьи решает seed.
   Акты без узлов дерева не участвуют.
4. **Загрузка и проверка:** HTML скачан для той же редакции. Проверено, что все `np`/`npe` есть в HTML и диапазон
   каждого узла лежит внутри родителя. Прошли все 100 из исходного отбора, резерв не понадобился.
5. **Разбиение:** в каждой группе round(30%) актов по seed ушли в holdout. `split.json` записан до начала
   разработки (sha256 `bea6a9be…`). **Holdout не открывать и не использовать для настройки правил.**

## Что выяснилось об источнике

- **Дерево есть не у всех актов.** Из 737 проверенных официальное дерево было у 200 (27%). Чаще — у актов
  с изменениями и у актов 2020-х. Ноль узлов обычно означает, что разметки нет, а не что у акта нет структуры:
  у проверенного соглашения в HTML 361 нумерованный абзац при 0 узлах.
- **Нет вообще:** международные договоры (соглашения, договоры, конвенции, протоколы), акты Конституционного Суда,
  «Основы законодательства». У актов КС, «Основ» и большинства законов до 1993 г. в IPS нет даже текста. В actual.pravo
  эти акты находятся, но без содержимого редакций. Их 14 мест из согласованного состава отданы ПП (+5), ФЗ (+4),
  указам (+3) и РП (+2); исходные квоты записаны в `selection.json` (`quotas_round_1`).
- **Нет в источниках с официальным деревом:** приказы министерств и СанПиН (нет в IPS; в actual СанПиН 2.1.3684-21 не найден).
  Для них второй слой по-прежнему проверяется разметкой Codex на сканах пула.
- **Концы диапазонов бывают строками таблиц:** `npe` может указывать на `<tr id="r23">`. Первые две попытки загрузки
  искали id только на `<p>`, а потом только вида `p<N>`, и ложно отбраковали 11 актов. Обе попытки сохранены как
  `fetch-attempt-0{1,2}-superseded/`. Скрипт проекции пилота (`json_paragraph_owners.py`) тоже берёт только `<p>`:
  перед использованием на корпусе его нужно поправить так же.

## Ограничения

- **Перекос к Правительству и законам.** Ведомственных актов, СанПиН, договоров и актов КС нет.
- **Мало дробной нумерации** (2 акта), а она — главная трудность СП и СанПиН.
- **Кодексы дают больше половины узлов:** 6 кодексов дают тысячи узлов, поэтому считать меры по узлам без
  поправки на документ нельзя.
- **Это консолидированные редакции** с пометами «(В редакции…)», а не оригиналы публикаций.
- Признаки отбора посчитаны автоматически по деревьям всех кандидатов, включая будущий holdout. Тексты holdout
  при отборе не читались.
