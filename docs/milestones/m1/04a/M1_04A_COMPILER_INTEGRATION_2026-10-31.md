# М1-04А: подключение доработанных правил после П23

Дата: 31.10.2026. Основание — просьба владельца подключить прототип к основной сборке документов.

Обычная сборка PDF теперь использует правила, доработанные после П23. Раньше эти правила работали отдельно
в проверке сканов, а сборка документов использовала прежний разбор. Теперь результат этих правил поступает
в общий черновик документа и его HTML-отчёт. Повторное распознавание сканов не требуется.

## Что подключено

1. `src/legal_rag/corpus/ocr_owner_structure.py` — перенесённые правила определения того, к какому документу,
   разделу, пункту или подпункту относится каждая область скана. Алгоритм при переносе не менялся.
2. `src/legal_rag/corpus/ocr_owner_ast.py` — преобразование этого результата в общее дерево `legal-ast/2`.
   Оно сохраняет исходный текст, страницы и координаты, отдельные фрагменты абзаца, таблицы и их ячейки.
   Родительские узлы содержат ссылки на напечатанные номера; текст хранится в дочерних узлах ровно один раз.
3. Вызов этих модулей из обычной команды `corpus compile` для PDF. Экспорт результата `current` в проверке
   сканов тоже использует этот путь и учитывает только разобранные области.

Для абзаца через несколько областей сохраняются отдельные ссылки на источник. Представление для чтения
разделяет слова пробелами; исходный текст не переписывается. Надстрочные номера имеют одновременно
исходное отображение (`2¹`) и общую запись (`2.1`). Повтор напечатанного номера и отсутствие подтверждённого
заголовка не скрываются. Изменённый текст, источник, связь с пунктом или состав таблицы отклоняются проверкой.

Разбор официальных JSON и текстовых документов продолжает использовать прежние пути. Старый `pdf_tree`
и экспериментальный `docs/assets/ocr_logical_structure.py` сохранены для исторических сравнений.
Дальнейшая доработка правил ведётся в производственном модуле. Замороженный П23 остаётся прежним;
П24 этим подключением не замораживается.

## Проверки

- Все **237 известных сканов**: результат перенесённых правил полностью совпадает с сохранённым
  экспериментальным вариантом. Сравнивается весь результат, а не только итоговый процент.
- Проверка по эталонам: **51640/51704** без учёта различий раздела (`no_section`),
  **51626/51704** в строгом варианте (`strict`). Ухудшений относительно окончательной доработки нет.
- Партия 23: **2490/2497 (99,72%)** в обоих вариантах; каждый из 12 документов строго выше 99%.
  Это качество предложенного распределения областей, а не доля юридически допущенного текста.
- Полный набор тестов после последней правки отчёта: **974 passed**. Из них 206 проверяют правила и 25 —
  преобразование, обычную сборку и порядок абзацев в HTML.
- Ruff на изменённых Python-файлах: **All checks passed**. Проверка М0: **78/78**.
- **237/237** прошли проверку переноса и сохранности источника. Для **229** документов выполнены две сборки
  в разные каталоги и повторный запуск в тот же каталог: идентификаторы совпали, повтор вернул `unchanged`.
  Для восьми старых сканов проверено преобразование дерева; полная сборка этих восьми не заявляется.
- После отдельного исправления порядка абзацев в HTML все **229** отчётов сформированы заново в новый
  каталог: проверены порядок по исходным страницам/областям, наличие ссылок на фрагменты и одинаковый
  результат двух формирований. Содержимое черновиков и их идентификаторы не менялись.
- `git diff --check` без ошибок.
- Независимая проверка изменения завершена; замечания исправлены и подтверждены повторной проверкой.

## Ограничение реквизитов и Task 3

Правила могут предложить правильное распределение областей, даже если прежняя проверка реквизитов ещё
не умеет подтвердить вид акта. Сейчас эта проверка распознаёт прежде всего правительственные и санитарные
постановления; **160 из 237** документов остаются с `identity_unresolved` (включая многие приказы, законы
и распоряжения). У 77 реквизиты подтверждены этой проверкой. Исходный текст неподтверждённых документов,
таблицы и предложенные связи сохраняются в нерешённых блоках, но не выдаются за подтверждённое дерево.

Поэтому **99,72% на партии 23 не означает, что вся партия допущена в общий корпус**. Подключение завершает
перенос правил в сборку, но проверка реквизитов, оставшиеся ошибки и независимая проверка новых документов
остаются отдельной работой. Каждый PDF сохраняет `pdf_structure_unqualified`; юридический допуск не менялся.
Резервные документы Task 3 не открывались. Task 3 и М1-04А не объявляются пройденными.
