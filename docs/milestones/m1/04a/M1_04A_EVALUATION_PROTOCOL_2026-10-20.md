# М1-04А: протокол оценки структурного парсера

Дата: 20 октября 2026. Владелец попросил оформить протокол, по которому видно,
движется ли работа над этапом 3 (юридическая структура после OCR). Пороги
остановки в разделе 7 — **предложение**, их утверждает владелец. Протокол не
меняет критерии Task 3 и G13 из
[плана М1-04А](../../../plans/2026-10-17-m1-04a-ocr-structure.md); он описывает
работу до них.

## 1. Какую проблему решает

Цикл «прогнать на новом документе → получить 60% → доработать → перейти
к следующему» измеряет подгонку под уже виденные документы, а не способность
справиться с новым. Это уже случилось: прототип
[логических абзацев](M1_04A_LOGICAL_PARAGRAPHS_2026-10-17.md) давал 100% на
документах разработки, а первая независимая проверка дала 52% и 65%.

Протокол отделяет **измерение** (на документах, которых код не видел) от
**доработки** (на документах разработки) и делает главной метрикой результат
с первого раза.

## 2. Корзины документов

| Корзина | Что с ней можно делать | Сейчас |
|---|---|---|
| **Разработка** | Смотреть, отлаживать, писать правила | ПП №416, СП 3.1.3597-20, выборка СанПиН 2.1.3684-21, ПП №1156, изменения №2 от 12.02.2026 |
| **Регрессия** | Все документы разработки с эталоном. После каждой правки результат на них не должен падать | Те же 5 документов плюс уже измеренные из пула |
| **Проверочный пул** | Только разметить эталон и один раз прогнать замороженный код | Пуст: все размеченные документы уже измерены. Пополняется по разделу 3 |
| **Квалификационный резерв** | Не открывать до Task 3. Используется один раз, для G13 | СанПиН 2.3/2.4.3590-20, СП 2.4.3648-20, ПП №2314, ПП №564 (split `272ad403…`, см. [baseline](M1_04A_BASELINE_2026-10-17.md)) |

Правила перемещения:

- Документ из пула попадает в разработку **только после** записи результата
  с первого раза в журнал (раздел 8). Обратно в пул он не возвращается.
- Квалификационный резерв не расходуется на измерение прогресса. Проверочный
  пул нужен именно для того, чтобы резерв оставался нетронутым до Task 3.
- Частично размеченный документ (например, СП 2.1.3678-20, где размечены
  страницы 1–8) остальными страницами в пул не идёт: его уже видели.

## 3. Эталон

- Формат существующий: владелец каждой содержательной области (путь
  `S/II/4/в`, `S/AN4/2`, `A/1`) и признак «продолжение». Оценщик —
  [`evaluate_ocr_owner_gold.py`](../../../assets/evaluate_ocr_owner_gold.py).
- Эталон размечается **до** прогона проверяемого кода; его хеши записываются
  до прогона. Разметчик не смотрит выход парсера.
- Соглашения разметки фиксируются до разметки и записываются в эталон
  версией соглашения. Действующая версия —
  [соглашение v1](M1_04A_ANNOTATION_CONVENTION_v1.md): какие области OCR
  оцениваются (не `Picture` и не шум), подписи и отметки, признак `+`,
  грамматика `owner-path/2`, псевдонимы обозначений и равенство утверждённого
  текста и приложения. Если соглашение меняется, весь эталон перемечается и
  пересчитывается, старые числа сохраняются отдельно.
- Вход разметчика не содержит выходов этапов 2 и 3 (ни логических абзацев,
  ни склеек, ни владельцев парсера): его строит
  `docs/assets/build_m1_04a_annotation_input.py`, а
  `docs/assets/freeze_m1_04a_gold.py` хеширует его вместе с эталоном.
- **Источники новых документов для пула** (не реализовано):
  1. новые PDF других семейств через `sources` и OCR у владельца;
  2. автоматический эталон: для актов, у которых официальный
     структурированный текст pravo.gov.ru совпадает с опубликованным PDF
     (первая редакция без изменений), владелец области получается
     сопоставлением OCR-текста с официальным деревом. Ручная проверка — на
     выборке. Это даёт десятки документов вместо единиц.
- Эталон одного разметчика по тексту OCR — известное ограничение. Выборочная
  сверка с изображениями страниц и второй разметчик — до Task 3.

## 4. Цикл работы

1. Взять из пула следующую партию (2–3 документа). Разметить эталон, записать
   хеши.
2. Заморозить код: записать хеши кода и версию соглашения разметки.
3. **Прогнать один раз**. Записать результат в журнал: общий процент,
   метрики по этапам (раздел 5), ошибки по классам (раздел 6).
4. Перевести партию в разработку.
5. Дорабатывать общими правилами: закрывать **класс** ошибок, а не документ.
   Условия под номер, дату, название или хеш конкретного акта запрещены
   (см. [docs/AGENTS.md](../../../AGENTS.md)).
6. Прогнать регрессию по всем документам с эталоном. Падение на любом
   документе — повод разобраться до следующего шага, а не принять.
7. Новая заморозка — и к шагу 1.

## 5. Метрики по этапам

Общий процент скрывает, где ломается. Поэтому каждый прогон считает:

| Этап | Метрика | Как считается сейчас |
|---|---|---|
| 2. Логический текст | Склейка продолжений: верные / ложные / пропущенные | Есть в оценщике (`continuation tp/fp/fn`) |
| 2. Логический текст | Колонтитулы: исключены верно / ложно | Нет, добавить |
| 3. Области | Верная область (`A`, `S`, `S2`, `S/ANn`, цитата) | Частично: входит в строгий путь |
| 3. Владелец | Верный путь: строгий, без разделов, только номера | Есть |
| 3. Сноски и таблицы | Верный владелец сноски / таблицы | Нет в эталоне, добавить |
| Все | Ошибки **молчаливые** против **помеченных** как нерешённые | Есть только для LLM-гибрида; для правил — после появления меток |
| Все | Текст ровно один раз, повтор прогона побайтно совпадает | Есть в прототипе и компиляторе |

## 7. Признаки прогресса и условие остановки (предложение)

**Прогресс** — это рост результата с первого раза от партии к партии и
уменьшение числа **новых** классов ошибок. Рост процентов на документах
разработки прогрессом не считается.

**Предлагаемое условие готовности семейства актов:**

- не меньше 99% верных владельцев с первого раза на проверочном пуле этого
  семейства;
- ни одного молчаливого переноса текста в чужую область (`A` ↔ `S`, чужое
  приложение, чужая цитата);
- три партии подряд без нового класса ошибок.

После этого семейство идёт на Task 3: квалификационный резерв, полный
компилятор, независимые контроли по изображениям страниц. Готовность по этому
протоколу Task 3 и G13 не заменяет.

## 9. Решения владельца (21 октября 2026)

1. **Приложения.** Принят вариант «место плюс владелец»: узел приложения
   стоит там, где напечатан, а владелец (`owner`) указывается отдельно, если
   его доказывает подпись; иначе — явно нерешённый.
   - **Сокращения обозначений.** «СП» и «СанПиН» с одним и тем же номером —
     одно обозначение одного документа: «Приложение № 1 к СП 2.1.3684-21»
     принадлежит СанПиН 2.1.3684-21. Идентичность определяет номер
     обозначения, а вид документа сопоставляется по словарю сокращений
     (СП / СанПиН / «санитарные правила», ФЗ / «Федеральный закон», ПП /
     «постановление Правительства» и т. п.). Разные номера — разные документы.
     Это отменяет прежний запрет считать «СП» и «СанПиН» одним видом.
   - **Утверждённый текст — это приложение к акту.** Текст под «УТВЕРЖДЕН(Ы)»
     и текст под «Приложение … к постановлению» — один вид узла: документ,
     приложенный к акту, с владельцем `owner` = акт и своим обозначением, если
     оно есть (например, СП 3.1.3597-20). Пути `S/…` и `A/ANn/…` в эталоне
     для одного и того же приложенного документа считаются равными.
   - Перемечать эталон не нужно: прототип и эталон уже относят приложения
     «к СП 2.1.3684-21» к утверждённому СанПиН. Оценщик получает
     эквивалентность `S` ↔ `A/AN` для приложенных документов; строгие числа
     пересчитываются, прежние сохраняются.
2. **Пороги раздела 7 приняты** как предложено: не меньше 99% верных
   владельцев с первого раза, ни одного молчаливого переноса в чужую область,
   три партии подряд без нового класса ошибок.
3. **Пул.**
   - Брать максимально разнообразные документы разных категорий:
     федеральные законы, кодексы, указы, постановления и распоряжения
     Правительства, приказы ведомств, санитарные и иные правила.
   - Эталон готовится **автоматически**: сопоставлением OCR с официальным
     структурированным текстом pravo.gov.ru для актов, у которых он совпадает
     с опубликованным PDF; человек проверяет выборку.
   - OCR (dots.mocr в Docker OCR-Lab) запускает исполнитель этого проекта.
4. **LLM на этапе 3** — решение отложено до результатов новых партий.
