# М1-04А: карта задачи (состояние на 27.10.2026)

Одна страница, чтобы не путаться: как мы называем вещи, где мы сейчас, какие прототипы были и на чём их проверяли.
Подробности — в отчётах по ссылкам.

## 0. Как мы называем вещи (решение владельца 27.10.2026)

Четыре слова и одно правило номеров. Ими пишутся все новые отчёты для владельца.

| Слово | Что это | Вместо старых слов |
|---|---|---|
| **Прототип П<N>** | код разбора структуры (`docs/assets/ocr_logical_structure.py`), замороженный после шага N | версия, v<N> |
| **Шаг N** | доработка правил, после которой замораживается П<N> | цикл |
| **Сканы** | наши PDF-сканы оригиналов публикаций с эталоном, размеченным Codex вслепую; приходят **партиями** | пул, проверочный пул, стенд пула |
| **Официальные деревья** | акты с готовым деревом структуры с сайта IPS (чистый текст, без OCR); набор называется по дате: «деревья от 25.10», «деревья от 26.10» | корпус JSON, корпус v1/v2, проекция |
| **Проверка** | один прогон замороженного прототипа на данных, которых он не видел; эталон заморожен заранее. Только это — прогресс | мера, первый прогон, holdout |
| **Доработка** | всё остальное: данные, на которых уже писались правила или которые уже проверены; их числа — не прогресс | разработка, регрессия, dev |

**Правило номеров: шаг N → прототип П<N> → проверка на партии N.** Пример: шаг 11 закончен, его прототип — П11,
проверять его будет партия сканов 11.

В отчётах для владельца — простые слова: «ничего не сломалось» (вместо «регрессия без ухудшений»), «другие виды актов
не затронуты» (вместо «ворота семейств»), «текст ушёл в чужой документ» (вместо `cross_scope_v2`). Технические имена
остаются в `AGENTS.md`, коде и данных.

**Имена папок, файлов и метка версии в коде не меняются** (решение владельца 27.10.2026): в данных прототипы лежат под старыми именами (`…-prototype-v10-freeze/`,
`VERSION = "ocr-logical-structure/10-experiment"`), партии — `batch-NN`, деревья — `json-corpus/20261025-v1` и
`…/20261026-v2`. Соответствие — в таблице раздела 3.

## 1. Что строим

Из распознанного текста скана построить дерево владельцев: для каждой области страницы сказать, чья она — акта (`A`),
утверждённого документа (`S`, `S2`…), приложения (`…/AN1`), статьи, части, пункта, подпункта.

- Распознавание скана в строки (OCR dots.mocr) — задачи М1-04 и М1-04B, здесь оно уже дано.
- Строки в дерево — это М1-04А. Код — один прототип; после каждого шага его копия замораживается.

Готовность вида актов (раздел 7 [протокола](M1_04A_EVALUATION_PROTOCOL_2026-10-20.md)): **не меньше 99% верных
владельцев с первой проверки, ни один кусок текста не ушёл в чужой документ, три партии подряд без нового вида
ошибок.** Готовый вид идёт на квалификацию (Task 3); готовность её не заменяет.

## 7. Хронология шагов (кратко)

- **Шаги 1–7** (21–24.10): от 60% до ~95% на сканах; формы, приложения, сноски, таблицы.
- **Шаг 8** (25.10, П8): правила по официальным деревьям — на деревьях сильно помогли, на сканах почти не сработали.
- **Шаг 9** (26.10, П9): длинные шапки приложений, примечания статей, цитаты поправок в законах.
- **Шаг 10** (26.10, П10): только приказы — колонтитулы-отметки, поля карточек профстандартов, оглавления, примечания
  форм; другие виды актов не затронуты.
- **Шаг 11** (27.10, П11): только постановления — цитаты поправок в приложенных Изменениях (№728: 253 → 1 315 из 1 316);
  другие виды актов не затронуты. Проверен на партии 11: 76,7% (после решения о цитатах 84,6%).
- **Шаг 12** (27.10, будет П12): только приказы — отметки машинистки в колонтитулах ФНС, «Приложение № N» над грифом,
  длинные шапки образцов со строчной ссылкой, подпись образцов Минтруда; партия 11 84,6% → 99,7%, другие виды актов
  не затронуты. Заморожен как П12; проверен на партии 12: 97,5%.
- **Шаг 13** (27.10, будет П13): только регламент ФСБ — длинные подзаголовки при стиле подзаголовков, «Приложение: 1. …»
  перед «2. …», подписи образцов и «Директор»; партия 12 98,2% → 99,8%. Одно постановление (№262) правило Б2 тоже
  улучшило — владелец принял. Заморожен как П13; проверяется на партии 13.
