## 1. Исправление загрузчика

**Реализовано:** адаптер `publication-pravo-pool/3` принимает карточку с `name: ""`,
`name: null` или отсутствующим полем `name`. Это действует для любого вида документа,
если остальные обязательные поля проходят прежнюю проверку: дата, номер, вид,
именованный орган, составное обозначение, номер опубликования, дата публикации и
положительное число страниц. Название из одних пробелов и неверный тип значения
по-прежнему отвергаются. Отсутствующий номер не подменяется вымышленным.

Для проверки используется временное представление с `complexName`; в архив попадает
точный исходный ответ, включая `null` или отсутствие поля, с его SHA-256. В ленте
`null`/отсутствующее название представляется пустой строкой для существующих средств
отбора; исходная лента сохраняется отдельно без изменений. Замороженный
`publication-pravo/1` и его контракт М0 не менялись.

Проверки:

- Новые тесты сначала воспроизвели шесть отказов из-за названия. После исправления
  проходят 26 проверок адаптера, включая ошибочные реквизиты, конфликт сохранённой
  идентичности, неподдерживаемый файл и повторную загрузку без изменения источников.
- Итоговый полный прогон: **1289 успешных тестов**; журнал сохранён в
  `data/requisites-20261103/tests-final.log`.
- Ruff и проверка diff пройдены. М0: 78/78, нет блокирующих критериев или проблем
  доказательств (`data/requisites-20261103/m0-gate-final.json`).

### Реальный пример

[Карточка №1165-р от 08.05.2025](http://publication.pravo.gov.ru/api/Document?eoNumber=0001202505100031)
сейчас возвращает `name: null`, но содержит дату, номер, вид и Правительство РФ как
именованный орган. Прежний адаптер отказывал с `invalid_card`; на сохранённой ленте
за 10.05.2025 отвергал 15 из 38 записей по причине типа `name`.

Новый адаптер получил карточку и PDF дважды: **`new` → `unchanged`**.
PDF: 227454 байта, SHA-256 `8cd7bfa294df8f27fc317bf570dd8561539ee29cd720dc5b1f8741b1c38bc1cd`.
Карточка: SHA-256 `dcb63770896f797e7363b7377f944c86aaa406b5edc30c7fd131cacdf9d6056c`.
239 ранее сохранённых исследовательских файлов проверены по хешам и не изменены.

**Ограничение проверки:** обычный Python HTTP-транспорт получил два тайм-аута при
скачивании PDF, после успешного получения карточки. Ошибки сохранены. Для отдельного
успешного прогона в границе `urlopen` временно использован `curl.exe`, с теми же HTTP
URL и без переходов между протоколами. Все четыре ответа имели HTTP 200; обе пары
байт совпали. Это не исправление производственного транспорта.

Доказательства: `data/requisites-20261103/loader-live-01/`: `before.json`,
`archive/runs/` (тайм-ауты), `curl-request-*` (исходные ответы и заголовки),
`curl-archive/`, `result.json`.

## 2. Проверка на сохранённых документах

**Выполнено отдельное диагностическое измерение, а не изменение сверки в сборщике.**
Взяты все 229 документов партий сканов 1–23 из прежнего списка полных сборок.
Восемь более ранних сканов с другим размещением исходных данных и партия 24 в эту
выборку не включены. Не выполнялись новые OCR, разметка или построение структуры.

Для каждого документа проверена цепочка: манифест → запись источника → исходная
карточка с верным хешем → исходный PDF с верным хешем → сохранённое OCR того же PDF.
Также проверены идентичность и номер опубликования. Все **1606 входных файлов**
проверены по хешам повторно после измерения и не изменились.

- Карточки сохранены для **229/229**, четыре основных поля заполнены у **229/229**.
- Название пустое у **17/229**. Это само по себе не создаёт ручного задания.
- Повтор двух сохранённых полных лент новым загрузчиком: **38/38** и **13/13**,
  ноль отклонений. В первой ленте восстановлены ранее отвергавшиеся 15 записей
  с `name: null`; исходные байты обеих лент сохранены без изменений.

## 3. Неподтверждённые сведения и нагрузка на человека

Текущее решение владельца о независимом построении структуры сохраняется.
Для продолжения этой задачи принимаем следующие технические границы:

1. Пустое название при заполненных реквизитах не требует ручного просмотра.
   Полный номер сохраняет суффиксы: например, `1165-р` не равен `1165`.
2. Неподтверждённые реквизиты сохраняются отдельно с причиной и значениями обеих
   сторон. Они не мешают строить структуру, но не дают юридического допуска.
3. Отдельно учитываются: карточка не найдена источником; карточка не сохранена
   локально; поле пустое; ошибка доступа; вид пока не поддержан разбором OCR;
   значение не извлечено; извлечённые значения различаются. Тайм-аут не доказывает
   отсутствия карточки. В этом измерении обращения к сайту для 229 актов не было.
4. Ошибки доступа сначала проходят существующие ограниченные повторы; ограничения
   разбора исправляются в программе. Ни те, ни другие не следует автоматически
   считать заданиями на ручную юридическую проверку каждого документа.
5. После доработки разбора и повторного измерения на проверку направляются
   оставшиеся неполные и конфликтующие случаи со ссылками на карточку и скан.

**Ручная нагрузка пока не измерена для всей выборки.** Сейчас есть семь кандидатов
на проверку среди 82 постановлений (8,5%), а 147 документов ещё ждут расширения
разбора. Это не «всего семь ручных проверок» и не «154 документа без карточки».
Нулевая доля отсутствующих карточек в отобранных и успешно сохранённых документах
также не является оценкой всего портала. Численный предел ручной нагрузки пока не
устанавливается: сначала нужно измерение, охватывающее все выбранные виды актов.

Следующая реализация в этой задаче — самостоятельное извлечение четырёх реквизитов
из шапки/подписного блока для законов, приказов, распоряжений и указов, затем такая
же проверка с раздельными причинами. Сведения карточки нельзя использовать как
подсказку для выбора подходящего OCR-значения среди нескольких кандидатов.
IPS и actual.pravo потребуют своих правил полей; в нынешний прогон они не входили.

Доказательства: `data/requisites-20261103/audit.py`, `audit-01/results.json`
(229 строк с полями и причинами), `audit-01/bindings.json` (1606 хешей).
Скрипт и результаты закреплены в `evidence-hashes.json`; повторная проверка всех
входных хешей после полного набора тестов также пройдена.
Для повтора скрипт копируется рядом с исходным в новый файл, а `OUT` меняется на
новый каталог: существующий результат намеренно не перезаписывается.

## 4. Принятое упрощение: реквизиты из карточки

Владелец выбрал официальный источник реквизитов вместо обязательного повторного
извлечения из OCR. Расширять прежнюю сверку на 147 документов не требуется.
Семь расхождений распознанных значений сохраняются как диагностика качества текста;
они не отменяют реквизиты заполненной официальной карточки.

В PDF-сборку добавлены дата акта, полный номер с суффиксом, вид документа и список
именованных органов из карточки раздела официального опубликования. Название
необязательно. В черновике и HTML-отчёте явно указано происхождение этих полей;
исходный OCR-текст и прежнее решение OCR-сверки не переписываются.

Карточка выбирается по хешу, записанному при получении именно этого PDF.
Проверяются исходные байты/хеш, принадлежность записи источнику, номер опубликования,
заявленная идентичность, URL карточки и PDF, включая фактические адреса ответов.
Позднейший указатель на другую карточку не заменяет сохранённую пару произвольно.
Распознавание по-прежнему должно ссылаться на хеш того же PDF и пройти свои проверки.

Полная привязанная карточка получает статус «Из официальной карточки».
Нет привязанных сведений или обязательное поле пустое — отдельный статус
«Недостаточно сведений официальной карточки». Это не препятствует построению
диагностической структуры, но не даёт выдать документ за юридически допущенный.
Повреждённая или чужая привязка источника вызывает отказ до записи результата.

Нативные HTML/JSON-маршруты и проверка действующей редакции не менялись.
Предшествующие результаты с `identity_unresolved` остаются историческими:
новое решение применяется в новых сборках.

## 5. Исправление тайм-аута основного загрузчика PDF

Повтор штатного скачивания вновь завершился тайм-аутом на PDF при успешно полученной
карточке. Пользователь подтвердил быструю загрузку браузером и curl. Отдельная
диагностика разделила получение заголовков и чтение тела: Python получал HTTP 200
с правильным `Content-Length: 227454`, затем зависал до окончания времени ожидания.
Настроенного HTTP-прокси в этой среде не обнаружено.

**Причина различия запросов:** стандартный urllib принудительно добавляет
`Connection: close`, даже если передать другое значение в Request. На этом запросе
PDF передаётся не полностью. Изменение только этого заголовка воспроизвело сбой
также в curl; ошибка не связана с OCR или пустым названием.

| Контрольный запрос | Результат |
|---|---|
| curl с обычными заголовками | 227 454 байта, 0,290 с |
| curl + `Connection: close` | Тайм-аут 8 с, получено 226 615 из 227 454 байт |
| curl + `Accept-Encoding: identity` | 227 454 байта, 0,287 с |
| curl + оба заголовка | Тайм-аут 8 с, неполный PDF |
| Python с изменением только Connection на keep-alive | Две полные загрузки: 0,284 с и 0,277 с, прежний хеш PDF |

Реализован `publication-pravo-pool/4`: отдельный обработчик HTTP только для PDF
меняет Connection на keep-alive. Это по-прежнему стандартный Python HTTP-клиент.
Ответ и его соединение освобождаются после чтения; повторное использование общего
сокета не вводится. Curl и временная подмена функций для работы загрузчика не нужны.

Сохранены HTTP-маршрут, прежняя защита переходов за пределы HTTP-источника,
ограничение частоты запросов, фиксация URL/заголовков/хешей, проверка формата PDF
и обработка ошибок. Преждевременный конец тела с объявленной длиной даёт ошибку,
а не сохраняет частичный файл. Код и проверки замороженного М0 не менялись;
транспорт карточек и лент также остался прежним.

**Проверка основным загрузчиком:** новое получение **1,528 с**, повтор **1,817 с**,
результаты `new` → `unchanged`. Время включает карточку и паузу ограничения частоты.
Оба раза получен прежний PDF: 227 454 байта, SHA-256
`8cd7bfa294df8f27fc317bf570dd8561539ee29cd720dc5b1f8741b1c38bc1cd`.
Здесь не использовались curl, monkeypatch, переключение протокола или IP-адреса.

Пять тестов с настоящим формированием HTTP-запроса поверх искусственного сокета
сначала воспроизвели отказ, после исправления прошли. Проверены повтор загрузки,
HTTP-ошибка, тайм-аут, неполный ответ и запрещённый redirect с сохранением прежнего
успешного архива. Пройдена 31 проверка транспорта/адаптера без сетевого доступа.
Итоговый полный набор: **1311 тестов**, Ruff и М0 **78/78** пройдены.
Независимая проверка транспорта не выявила замечаний; проверяющий также отдельно
выполнил все 31 проверку. Прежние исходники и результаты не переписывались.

Доказательства: `data/requisites-20261103/transport-diagnosis-01/`:
`baseline.json`, `curl-comparison.json`, `python-keepalive.json`, `live-main-loader.json`,
`live-main-loader/`, исходные ответы контрольных запросов и журналы проверок.
