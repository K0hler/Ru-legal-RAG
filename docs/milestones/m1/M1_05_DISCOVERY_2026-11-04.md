# М1-05: поиск поправок через общий OCR

**Дата:** 04.11.2026. **Статус:** М1-05 реализована и проверена.

Поиск публикаций из М0-10А читает общий `text-extraction/1`, переданный через
`--extraction-index`. Отдельное распознавание через Poppler/Tesseract удалено.
OCR нужен для ссылок внутри PDF: общее название «О внесении изменений…»
не определяет изменяемый акт. Загрузка PDF, отдельный `corpus extract` и
повтор поиска остаются явными этапами. `sources` не импортирует компилятор
и не запускает распознавание.

## Проверка на сохранённых официальных материалах

- Сохранённая лента 26.09.2026 прочитана без заранее переданного номера
  публикации: 13 событий, два выбранных постановления. Для №1241 достаточно
  явной ссылки в официальной карточке; №1242 требует текста PDF.
- Без извлечения №1242 загрузился, но дал одно повторяемое исключение и
  не пометил прежний кандидат №491 устаревшим.
- Встроенный `legal-rag-dotsmocr` распознал все три страницы официального
  PDF №1242. Проверены модель, образ, настройки и сохранённые исходные ответы.
- По странице 3 создана связь №1242 → №491 с SHA-256 PDF и общим extraction ID.
  Два запуска поиска дали `new`, затем `unchanged`, один и тот же отчёт и
  одну инвалидацию кандидата. Повторная синхронизация сохранённого официального
  текста вернула `unchanged`; кандидат остался `stale`, его передача отклонена.
- Повтор из сохранённых OCR-ответов дал побайтово одинаковый индекс и тот же
  extraction ID. Все 172 файла исходного архива М0 остались неизменными.

## Совместимость с М0

База до изменения — `4d433f32a36ae296fc0a7f01e094981e2b44129b`.
`publication-event/1`, `publication-discovery/1`, `edition-candidate/1` и
их версии не изменены. Сводка извлечения в source item сохраняет прежние ключи
`method`, `extraction_id`, `source_asset_sha256`, `pages[{page,text}]`.
Архивируемое общее извлечение имеет собственную версию `text-extraction/1`.
Новые extraction ID ожидаемо изменяют ID новых отношений; старые отношения
и собственные OCR-результаты М0 не переписываются.

До обновления freeze М0 корректно заблокировал изменённые код и тест.
После проверки совместимости обновлены только хеши `sources/__main__.py`,
`discovery.py`, сценарного теста и добавлен хеш нового читателя `extraction.py`.
В assessment обновлены хеш этого теста и хеш изменённого freeze-манифеста.
Ни один хеш исторических исходников или результатов не обновлялся.
М0 повторно прошёл 78/78 без проблем с доказательствами.
Побайтовый пример `edition-candidate/1` сохранил SHA-256
`173d5d60023a78408259af1999dbabce789008128e38427b702f732f249299be`.

## Проверки кода и границы результата

Сценарные тесты используют настоящий нормализатор и поддельный транспорт.
Проверяются отсутствие/повреждение индекса, неверный PDF, пропущенные и
повторные страницы, неправильные координаты, текст вне указанного фрагмента,
номер-префикс, повтор и таблица с проекцией текста.
Независимое ревью выявило один дефект: строка локатора могла быть согласована
сама с собой, не указывая на существующий текст. После воспроизведения
добавлены проверки реального региона, целочисленных границ и исходного текста;
отрицательные тесты прошли цикл RED → GREEN.

Полный набор тестов: **1401 passed** на Python 3.13.12. Отдельная проверка
источников через `unittest`: **48/48**. Ruff и `git diff --check`: пройдены.
М0: **78/78**, без проблем с доказательствами.
Первый полный запуск в `.venv` остановился на отсутствующем Pillow; пакет
12.1.0 установлен в локальное окружение Python 3.13.12. Попытка с системным
Python 3.14 остановилась на отсутствующем tinycss2; окончательная проверка
проводится на Python 3.13, без изменения зависимостей продукта. В полном
прогоне из `.venv` получено 1400 успешных тестов и один отказ неизменённого
`test_matching_model_starts_the_command`: запуск через `os.execvp` не создал
ожидаемый файл. Во временном окружении Python 3.13.12 с путём без пробелов
все пять тестов того же проверяющего модуля проходят; используются те же пакеты
из `.venv/Lib/site-packages`. Этот полный повтор записан в
`data/m1-05-full-tests-clean-path.log`. Старый отказ и его условия сохранены;
код запуска модели и его тест не изменялись.

Это проверка ограниченного сценария поиска поправок по сохранённой ленте.
Она не доказывает полноту истории поправок, поддержку произвольного юридического
содержания или юридический допуск редакций. Независимая квалификация структуры
PDF/OCR по G13 остаётся в последующих задачах М1.

## Последующее исправление запуска, 04.11.2026

Описанный выше отказ штатной `.venv` устранён по отдельному поручению владельца.
Причина подтверждена: Windows `os.execvp` не экранировал путь и аргументы.
Проверяющий скрипт теперь использует в Windows subprocess со списком аргументов
и передачей кода завершения; Linux сохраняет exec. Полный набор **1403 теста**
прошёл прямо в проектной `.venv`, временное окружение больше не требуется.
[Диагностика, исправление и проверка образа](04b/M1_04B_WINDOWS_LAUNCH_FIX_2026-11-04.md).
