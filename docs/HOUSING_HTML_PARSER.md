# Парсер HTML ЖК РФ

## Реализовано

Отдельный диагностический профиль `housing-code-html/1` в
`src/legal_rag/corpus/housing_html.py`. Он читает исходный UTF-8 HTML,
использует общий native HTML tokenizer и сохраняет все текстовые токены,
исходные фрагменты, координаты, декодирование entities, нормализацию пробелов,
классы абзацев, HTML anchors и команды ссылок. Новых runtime-зависимостей нет.
Существующие компилятор 59-ФЗ, source-adapters, permission/admission contracts
не изменены.

Перед адресацией сверяются название ЖК РФ до первой статьи и единственный
финальный президентский блок с номером 188-ФЗ и датой 29 декабря 2004 года.
Это совпадение идентичности по источнику, не установление достоверности
редакции или её действия на дату. `edition_admission=false`,
`valid_from=null`, `valid_to=null`; дата из имени файла не импортируется.

### Структура

- `Z`: название; `T` + «РАЗДЕЛ»: раздел; `H` + «Глава»/«Статья»: главы/статьи.
- Части `1.`, пункты `1)`, буквенные подпункты `а)` и ненумерованные абзацы.
- Пункты могут быть непосредственно в статье без фиктивной части.
- Статьи могут быть непосредственно в разделе без фиктивной главы.
- Надстрочные `W9`/`WB`/`sup` сохраняются как отдельные компоненты номера.
  Адрес `act/article/32.1` не превращается в `act/article/321`.
- `text` сохраняет исходные декодированные символы после нормализации только
  пробелов; `display_text` отдельно отображает надстрочные цифры. Для адресов
  используйте `number_canonical`/`address`, не цифры из плоского `text`.
- `mark`/`markx` сохраняются отдельными примечаниями, включая соседние spans.
  История редакции, утрата силы, применение, конституционные оговорки и будущие
  изменения различаются как исходные заявления, не подтверждённые статусы.
- Только примечание в том же HTML-абзаце наследует адрес нормы. Отдельные
  примечания имеют родителя `act`, `scope_status=unresolved`; соседство с
  предыдущей нормой не устанавливает область применения.
- Повторные адреса/anchors, неизвестные заголовки/маркеры, несколько норм через
  `<br>` и неподдерживаемые HTML tables/lists остаются `unresolved_block` и
  останавливают адресацию до распознанной границы.
- Неподдерживаемые `img`/`table`/`ul`/`ol`, включая элементы без текста,
  сохраняются в `extraction.unsupported_regions` с координатами и исходным
  HTML, а в AST — в `unresolved_regions`. Они блокируют адресацию и техническую
  полноту. Текстовые токены и структурные регионы учитываются независимо;
  валидатор повторно извлекает регионы из исходных байтов для сверки покрытия.
- После отвергнутого заголовка главы/раздела предыдущий родитель сбрасывается.
  Границы внутри одного абзаца обнаруживаются и через группы inline-примечаний.
- Примечания `A`/`F`/`mark`/`markx` не могут поставлять реквизиты идентичности.
  Валидатор сверяет числовые координаты с закодированными в `locator`.

`nodes` — список в исходном порядке с `parent_address` и `children`.
Идентификатор узла зависит от исходного SHA-256, версии профиля и адреса.
Координаты — полуоткрытые Unicode codepoint offsets в декодированном UTF-8
HTML; это не байты файла и не физические страницы.

## Запуск

Из корня `H:\AI_AGENT\Legal RAG` в имеющейся Conda-среде:

```powershell
$env:PYTHONPATH = "src"
python -m legal_rag.corpus.housing_html --input "data/m0-10-review/official/01-housing-code-2026-09-01.html" --output-dir "data/m1/pilot_runs/housing-html-parser-v3"
```

CLI создаёт `extraction.json`, `ast.json`, `validation.json`, `report.html`.
Отчёт автономный: раскрываемое дерево и исходный HTML как экранированный
текст; скрипты и ссылки из исходника не исполняются. Отчёт не требует сети.

Первый запуск возвращает `new`, идентичный повтор — `unchanged`.
Несовпадающий существующий результат не перезаписывается: укажите новый
каталог. При неразобранном содержимом диагностические артефакты сохраняются,
но exit code равен `2`; ошибки входа/целостности также дают `2`.
Нормально распознанный диагностический документ даёт `0`, не юридический допуск.

## Границы качества

Это профиль конкретного семейства HTML ЖК РФ, **не универсальный парсер всех
актов**. ПП РФ с утверждаемыми Правилами/приложениями, таблицы, формулы,
изображения, PDF/OCR и историческая реконструкция требуют отдельных профилей.
Нумерация ненумерованных абзацев — техническая; их родители определяются
синтаксическим состоянием. Нельзя выдавать эти ordinal как подтверждённые
юридические номера абзацев без контрольной разметки. Полный человеческий gold
для всех вложенных родителей не создан; закрытый набор не использовался.

Нулевое число нераспознанных блоков означает механический разбор по этому
профилю, а не независимо измеренную 100% точность юридического дерева.
Отдельная область применения standalone notes остаётся неразрешённой.
Переход к продуктовому RAG требует проверки таких связей и существующих
source/temporal/admission gates, а не автоматического допуска из этого CLI.

## Регрессии

```powershell
$env:PYTHONPATH = "src"
python -m pytest tests/legal_rag/corpus tests/legal_rag/sources -q --cov=legal_rag.corpus.housing_html --cov-report=term-missing
python -m ruff check src/legal_rag/corpus/housing_html.py tests/legal_rag/corpus/test_housing_html.py
python -m mypy src/legal_rag/corpus/housing_html.py --ignore-missing-imports --follow-imports=skip
python docs/assets/generate_m0_gate.py
```

Fixtures — авторские учебные примеры прямо в тесте, не копии реального ЖК РФ,
не private gold и не сетевые тесты. Основные проверяемые случаи: literal tree,
entities/whitespace/source coordinates, superscript identity, adjacent notes,
marker-only repealed provisions, unknown/duplicate structures, malformed HTML,
identity conflict, immutable replay, corrupted output и безопасный HTML report.
