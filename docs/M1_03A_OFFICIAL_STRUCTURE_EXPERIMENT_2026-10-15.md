# М1-03А: эксперимент с официальной структурной разметкой

Дата: 15 октября 2026 года. Статус: отдельный локальный эксперимент, разрешённый
владельцем проекта. Производственный конвейер М0/М1 и замороженные контракты
не изменены. Юридический допуск редакций и завершение М1-03А/G13 не выданы.

## Вывод

**Официальная JSON-разметка подходит как основа дерева, но её недостаточно для
полного юридического AST.** Все 3 906 исходных узлов семи актов удалось связать
с оригинальным HTML, нормализовать и воспроизводимо сохранить вместе с текстом.
Все 3 894 узла с явно указанным номером прошли сверку номера с исходным HTML.

При более глубокой проверке обнаружились реальные пробелы: разметка пропускает
внутреннюю структуру некоторых цитируемых изменений и списков в формах. Раннее
утверждение о «готовом юридическом дереве» следует понимать как готовую структуру
уровней, предоставленных источником, а не как доказанную полноту всех уровней.

Предлагаемый маршрут: **М0 сохраняет HTML и JSON одной редакции; М1 строит основу
из JSON и дополнительно разбирает содержимое, не представленное отдельными
узлами.** Неоднозначные фрагменты остаются явно неразрешёнными.

## Что выполнено

Эксперимент использует семь уже разрешённых диагностических документов:
четыре обязательных оригинала и три неудачных документа из проверки расширения.
Новые модели, внешние сервисы извлечения и OCR не применялись. Разбор выполнялся
локально по сохранённым ответам официальных API и неизменённым исходным текстам.

1. Проверены разрешения, идентичность акта, хеши исходников и привязка JSON
   к выбранной редакции. В предыдущем исследовании все семь свежих текстовых
   ответов побайтно совпали с архивами; их хеши повторно проверены здесь.
2. Из `id`, `lvl`, `np`, `npe` восстановлены родители и полные HTML-диапазоны.
   Номера сохранены строками с отдельным отображением надстрочных индексов.
3. Типы источника сопоставлены с экспериментальными типами нашего дерева.
   Например, пять объектов `unit=вложение` в №354 разделены на два утверждённых
   текста, раздел примечаний и два отдельных примечания.
4. Существующий неизменённый HTML-экстрактор использован для получения текста,
   редакционных примечаний, координат, таблиц и изображений. Его юридический
   движок не использовался для построения нового дерева.
5. Каждый текстовый блок сохранён один раз и связан с наиболее глубоким
   охватывающим узлом, либо явно отнесён к контексту документа/техническому
   содержимому. Общий текст родителя не дублирует отдельное хранение потомков.
6. Независимый DOM-разбор проверил номера, текст каждого абзаца, весь текст тела
   документа после исключения портальных элементов, таблицы и адреса изображений.
7. Для каждого акта выполнены два полных построения, сравнение хешей дерева
   и контролей, затем неизменяемый повтор записи результата.

Это самостоятельный экспериментальный формат, не новая версия производственного
`corpus-input/1` или допущенного `LegalEdition`. Связь редакционных примечаний
с диапазоном текста сохраняется, но их юридическая область действия отдельно
не квалифицирована.

## Проверенные содержательные примеры

### ЖК РФ: вложенность и сложные номера

Под пунктом `2¹` статьи 12 получены семь отдельных подпунктов `а–ж` с правильным
родителем. Пункт имеет исходный ID `si_h1_a12_j2:1~`, подпункты — его дочерние ID.
Индекс `1.1-1` также сохранён без склейки надстрочной части с основным номером.

Для всего кодекса сохранены 12 разделов, 21 глава, 243 статьи, 1 085 частей,
683 пункта и 7 подпунктов. Отдельно сохранены 996 блоков редакционных примечаний.

### №261-ФЗ: цитируемые статьи другого акта

В исходном HTML есть два заголовка внутри поправок:

- `p408`: цитируемая статья 9.16 о нарушении законодательства об энергосбережении;
- `p759`: цитируемая статья 23.71 о федеральном органе контроля.

Оба заголовка и их текст сохраняются под соответствующими пунктами статьи 37
исходного №261-ФЗ. Они не превращаются в самостоятельные статьи самого №261-ФЗ.
Однако JSON не предоставляет для них отдельных узлов и внутреннего поддерева.
Следовательно, одна только официальная разметка не выделяет нужный контекст
цитирования и не закрывает прежнюю проблему полностью.

### №410: приложение к утверждённым Правилам

Узел `zf1_uf2` имеет тип приложения и родителя `zf1` — утверждённые Правила.
Прежний сбой сопоставления заголовка приложения с оговорками редакции удалось
обойти благодаря явной связи источника. Ненумерованному приложению не придуман
номер. При этом в изменениях актов остаются цитаты, которые JSON отдельно
не типизирует; результат всего документа ещё не считается полным.

### №47: приложения и формы

Сохранены три приложения и все шесть таблиц, включая 22 строки и 42 ячейки.
Приложение №2 — форма акта обследования — связано с утверждённым Положением.

Внутри формы после слов «Приложение к акту» есть пять элементов:
`p350–p354`, пункты `а–д`: результаты инструментального контроля, лабораторных
испытаний, исследований, заключения экспертов и другие материалы.
Все пять присутствуют в тексте, но отдельные структурные узлы для них JSON
не предоставляет. В экспериментальном дереве они пока остаются содержимым формы.
Для полного разбора вложенных списков нужен дополнительный проход.

### №354: примечания и более подробная структура

Общий тип источника «вложение» успешно разделён по содержанию. При этом найдено
86 кандидатов на дополнительные нумерованные фрагменты и 21 кандидат на цитату.
Прежний native-компилятор имел здесь 20 узлов цитат и более подробную структуру.
Старый компилятор используется только для сравнения, не как эталон правильности;
разница счётчиков сама по себе не доказывает ошибку JSON.

Пример показывает, почему официальной разметкой нельзя без проверки заменить
уже работавший более подробный разбор: часть структуры цитат и форм потребуется
сохранить или восстановить дополнительно.

## Примечания и границы проверенности

Во всех документах сохранены 2 122 блока редакционных примечаний. У 17 нет
охватывающего структурного диапазона JSON: они явно остаются без такого владельца,
с исходным текстом и координатами. Это не потеря данных. Автоматически назначать
им юридическую область действия по соседству эксперимент не пытается.

Связность дерева и совпадение исходных номеров не доказывают правильность всех
юридических ролей, применимость редакции на дату или полноту будущих поправок.
Семь актов здесь — диагностический набор разработки. Проверку переноса на новых
полных актах после фиксации правил этот эксперимент не заменяет.

## Проверки и воспроизведение

Экспериментальный адаптер:
`docs/assets/experiment_official_structure.py`.
Отдельная проверка доказательств и генератор русского автономного просмотра:
`docs/assets/check_official_structure_experiment.py`.

Окончательный прогон: `data/m1/experiments/official-structure-20261015-v1/attempt-05/`.
Файл `index-v2.html` содержит семь документов, поиск узлов, исходные фрагменты
и переходы к кандидатам на неразобранную структуру. Ему не нужен внешний сервер
для доступа к данным. Исходный HTML отображается в изолированной рамке
с запретом внешних ресурсов; сами оригиналы не редактируются.

Проверки:

- Отрицательные проверки отвергают пропавший якорь, повтор ID в HTML/JSON,
  неверного родителя, скачок уровня, пересечение соседних диапазонов
  и обратные границы. Неверный номер в подписи выявляется отдельной сверкой.
- Десять проверок конкретных примеров подтверждают перечисленные выше результаты.
- 189 тестов существующих модулей corpus и sources прошли за 35,82 с.
- Ruff для двух новых исследовательских сценариев пройден.
- M0 gate повторно сгенерирован: 78/78, проблем доказательств нет.

Основной эксперимент выполнен на Python 3.14.0 и BeautifulSoup 4.15.0.
Четырнадцать полных построений, проверки и запись по документам заняли суммарно
26,424 с. Это время всего сценария с двумя построениями каждого документа,
а не замер чистой скорости парсера и не сравнение с другими движками.
Регрессионные тесты запускались в отдельном окружении с pytest 8.4.2,
BeautifulSoup 4.14.3 и tinycss2 1.4.0; глобальные зависимости не менялись.

Для повторения:

```powershell
python docs/assets/experiment_official_structure.py --self-check
python docs/assets/experiment_official_structure.py --output data/m1/experiments/official-structure-20261015-v1/new-attempt
python docs/assets/check_official_structure_experiment.py --attempt data/m1/experiments/official-structure-20261015-v1/new-attempt
```

Каждое новое построение требует нового каталога. Предыдущие попытки сохранены:
ошибка предположения об одинаковом коде успеха JSON двух банков и первые ошибки
контрольного читателя номеров не скрыты. У `actual` успешный `status=0`, у `ips`
в сохранённом ответе — `status=200`; это разные форматы адаптеров. Общие поправки
читателя учитывают голые маркеры утративших силу положений, переносы `br`
и римские номера без слова «РАЗДЕЛ».

## Следующий шаг

Получение и архивирование официального JSON стоит включить в маршрут М0 после
проверки совместимости контрактов. В М1 следует сохранять предоставленные
источником узлы как основу, а дополнительный разбор направлять на цитаты,
списки в формах и другие неохваченные структурные фрагменты. Расхождения между
источником и дополнительным разбором должны оставаться проверяемыми.

Переход к интеграции не означает автоматического завершения М1-03А. Полный AST,
область действия примечаний, новые контрольные акты и допуск редакций остаются
отдельными проверками. Исходные провалы native-компилятора и Documind сохранены.
