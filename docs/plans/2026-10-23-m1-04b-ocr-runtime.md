# М1-04B: собственный рантайм dots.mocr в Legal RAG — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** запланировано 23.10.2026 по просьбе владельца. Выполнен только страховочный шаг (задача 0). Остальное не начато.

**Goal:** перенести в Legal RAG только то, что нужно для распознавания dots.mocr: образ, клиент, настройки и проверку модели. Новые прогоны больше не должны зависеть от испытательного полигона OCR-Lab с его 12 движками. Формат доказательств и все замороженные результаты не меняются.

**Architecture:**
- Docker остаётся границей: Legal RAG не загружает GPU-библиотеки, модель работает в контейнере.
- Собственный минимальный образ, `compose` с одним сервисом, клиент только для dots.mocr — под git, с обычными тестами.
- Выход прежний: `ocr-results/1`, экспорт `dotsmocr-layout/2`, нормализатор `pdf_extraction.py` без изменений.
- Путь через OCR-Lab остаётся только для перепроверки уже сохранённых доказательств.

**Tech Stack:** Docker, vLLM 0.11.0 (как сейчас), Python 3.13 на хосте (стандартная библиотека), pytest, ruff.

**Spec:**
- анализ 23.10.2026 (ниже, «Исходное состояние»);
- [M1-04: общий PDF/OCR](../milestones/m1/04/M1_04_PDF_OCR.md) и [приёмка M1-04](../milestones/m1/04/M1_04_ACCEPTANCE_2026-10-16.md);

## Global Constraints

- Замороженные данные (пачки M1-04A 1–5, прогоны M1-04, эксперименты) не перезаписываются. Их перепроверка из сохранённых доказательств должна давать те же `extraction_id`.
- Формат выхода и нормализатор не меняются. Если без изменения нельзя, это отдельное решение с новой версией контракта.
- Свежее распознавание не обещает побайтного совпадения (это уже измерено). Новый рантайм квалифицируется сравнением, а не равенством хешей.
- Хост Legal RAG по-прежнему не ставит GPU-пакеты, не скачивает веса и не запускает и не останавливает чужие контейнеры.
- Новые зависимости образа — только с точными версиями и digest базового образа. Ничего «последней версии».
- Ничего из OCR-Lab не удаляется и не меняется, кроме чтения. OCR-Lab остаётся полигоном.
- Каждая задача — отдельный коммит в `main` с обновлением ближайшего `AGENTS.md`.

## Review Focus

1. **Скрытые зависимости.** Всё, что dots.mocr реально берёт из образа TeleOCR (PyMuPDF, версии transformers/fastapi, процессор модели с `trust_remote_code`), должно стать явной закреплённой строкой.
2. **Равноценность распознавания.** Новый рантайм не хуже старого на уже проверенных документах; различия записаны и объяснены, а не скрыты.
3. **Изоляция.** Контейнер видит только модель (только чтение), свой вход и свой выход. Никаких общих кэшей других движков.
4. **Отпечаток.** По `runtime.json` однозначно видно, каким рантаймом (старым или новым) распознан документ.
5. **Повторяемость сборки.** Образ можно пересобрать с нуля на чистой машине по файлам репозитория и манифесту модели.
