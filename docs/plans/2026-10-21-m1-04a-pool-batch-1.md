# М1-04А: первая партия проверочного пула с автоматическим эталоном — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** получить первую партию разнообразных новых актов: оригинальные PDF, OCR dots.mocr, автоматический эталон по официальному дереву pravo.gov.ru. Затем один раз прогнать на ней замороженный прототип и записать результат с первого раза в журнал протокола.

**Architecture:** акты отбираются случайной выборкой из ленты publication.pravo.gov.ru только по метаданным, до чтения текстов. Загрузка идёт через существующий жизненный цикл `sources`, официальное дерево — через `structure_bundle` и `official_import`. OCR запускает исполнитель (Docker OCR-Lab). Эталон строится сопоставлением текста OCR-областей с текстом официальных единиц. Сопоставитель сначала проверяется на документах, у которых уже есть ручной эталон. Все новые данные лежат в `data/m1/m1-04a/` по схеме из `data/AGENTS.md`.

**Tech Stack:** Python 3 стандартной библиотеки (`difflib`, `random`), существующие коннекторы `legal_rag.sources`, `legal_rag.corpus.logical_text`, Docker OCR-Lab `ocr-lab/dotsmocr:2026-10-10`, pytest 8.4, ruff 0.14.

**Spec:** [протокол оценки](../milestones/m1/04a/M1_04A_EVALUATION_PROTOCOL_2026-10-20.md), разделы 2–9 и решения владельца 21.10.2026 (раздел 9).

## Global Constraints

- Отбор — только по метаданным (тип, дата, число страниц, число редакций). Тексты отобранных актов не читаются до заморозки отбора; хеш `selection.json` записывается до загрузки PDF.
- Автоэталон строится только для актов с **ровно одной** официальной редакцией: текущая редакция совпадает с опубликованной. Акты с изменениями (в том числе все кодексы) в эту партию не входят.
- Сеть — только через существующие коннекторы `legal_rag.sources`: HTTP API publication.pravo.gov.ru, actual.pravo.gov.ru, IPS. Новых эндпоинтов нет.
- Квалификационный резерв (`documents/reserved/`) не открывается.
- Никаких условий под номер, дату, название или хеш конкретного акта — ни в сопоставителе, ни в оценщике.
- Выходы неизменяемы: повторный запуск пишет в новую папку или отвечает `unchanged`.
- Новые данные лежат только в `data/m1/m1-04a/{documents/pool/batch-01,ocr,gold,experiments}/`.
- Отчёты на русском. Каждый Task заканчивается коммитом в `main`.
- Команды — PowerShell из корня репозитория: `$env:PYTHONPATH = "src"; .venv\Scripts\python.exe …`.

### Task 5: Сопоставитель автоматического эталона

**Files:**
- Create: `docs/assets/build_auto_gold.py`
- Test: `tests/legal_rag/corpus/test_auto_gold.py`

**Interfaces:**
- Consumes: `logical-text/1` (регионы, роли, `match_text`) и официальное дерево `legal-ast/2` из `official_import`: единицы с полями вида единицы (`unit`), отображаемого номера, родителя и текстового диапазона.
- Produces: `build_auto_gold(logical: dict, official: dict) -> dict`:
  - `gold_lines` — строки в формате эталона: `<page>.<index> <path>[|<path>] [+]`;
  - `regions` — по каждой области: `key, owners, confidence, reason`;
  - `excluded` — счётчики по причинам;
  - `unit_kinds` — встретившиеся виды единиц.

  CLI: `build_auto_gold.py --logical … --official … --output gold/<slug>/auto-<slug>.gold.txt` пишет ещё `auto-<slug>.match.json` и `.sha256`.

**Алгоритм:**
- нормализация обеих сторон: `match_view`, нижний регистр, `ё→е`, убрать всё, кроме букв и цифр;
- официальные листовые единицы склеиваются в одну строку с картой «символ → единица»;
- содержательные области OCR (`role=content`, кроме `Table`/`Picture`) склеиваются в порядке логического текста;
- выравнивание — `difflib.SequenceMatcher(autojunk=False)` по блокам. Длинные документы выравниваются окнами по страницам с монотонным курсором, чтобы не уходить в квадратичное время;
- владелец области — единица, которой принадлежит не меньше 70% совпавших символов области. Если две единицы получают по 30% и больше — два владельца через `|`. Если совпало меньше 60% символов области — исключить с причиной `no_official_match`;
- путь владельца строится по таблице видов `unit → сегмент owner-path/2`: статья, часть, пункт, подпункт, абзац, глава, раздел, параграф, приложение, утверждённый документ. Незнакомый вид — исключение с причиной `unknown_unit_kind`;
- `+` (продолжение) ставится, если предыдущая содержательная область относится к той же единице и стоит на предыдущей странице.
