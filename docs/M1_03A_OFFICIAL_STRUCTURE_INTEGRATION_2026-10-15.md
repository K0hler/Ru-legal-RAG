# М1-03А: интеграция официальной структуры

Дата: 15 октября 2026 года. Статус: маршрут М0 → М1 реализован и проверен
диагностически. Полная структурная готовность, G13 и юридический допуск не выданы.

После подтверждения владельцем проекта реализовано предложение из
[эксперимента](M1_03A_OFFICIAL_STRUCTURE_EXPERIMENT_2026-10-15.md): приобретать
HTML и JSON одной редакции, использовать JSON как исходный каркас и доразбирать
конструкции, которых в нём нет. При ошибке переданный JSON не игнорируется.

## Что работает

М0 получает карточку/редакции, HTML и отдельный JSON структуры. HTML остаётся
исходным JSON-ответом с полем `redtext` или `doctext`; вложенная строка HTML
не подменяет исходный архив. JSON структуры сохраняется отдельным активом
`official_structure`. Адреса API остаются внутренними деталями адаптера.

Новая точка входа использует прежние адаптеры и acquisition lifecycle:

```powershell
$env:PYTHONPATH = 'src'
python -m legal_rag.sources.structure_bundle `
  --source actual `
  --document-hash 4c8dcb690700cdc95a209ca40db2bb177cfc85916d6cfef83439b8696fbf546f `
  --data-dir data/m0-official-structure
```

Для нового банка используется `--source ips`. Производственные ограничения
адаптеров сохранены: два пилотных документа actual и два ips. Семь документов
диагностического прогона не расширяют этот allowlist. Старые команды acquisition
и pilot сохранены; для приобретения с разметкой предназначена новая точка входа.

Она возвращает обычный результат acquisition и путь `structure_bundle`.
Новая запись `official-structure-bundle/2` хранится неизменно в
`structure_bundles/<content-id>.json` и содержит:

| Поле | Назначение |
|---|---|
| `source_system`, `source_item`, `document_hash`, `source_url` | Источник и публичная карточка документа |
| `selector.database/document_id/edition_id` | Один выбранный документ и редакция для обоих запросов |
| `text_sha256`, `structure_sha256` | Точные исходные байты HTML-ответа и структурного JSON |
| `edition_evidence_sha256` | Архивная карточка/список редакций, подтверждающие выбор |
| `transport_evidence.text/structure` | Адреса запроса и ответа именно этого получения |

Отдельный транспорт нужен даже при неизменном SHA файла: две редакции могут
иметь одинаковую структуру. Метаданные первого сохранения файла не переписываются,
а каждая связка хранит свой захват. Проверяются оба URL, включая редирект внутри
того же домена; пустой дубликат параметра редакции тоже отклоняется.

Версия связки `/1` сохранена для ранних архивных импортов. Она использует
транспорт из asset metadata и проверяет конечный URL, когда тот записан.
Отсутствующий конечный URL старого исследования не выдумывается. Новый М0
обязательно записывает и проверяет оба адреса через `/2`.

## Вход М1 и представление дерева

`corpus-input/2` содержит один актив `consolidated`, один `official_structure`
и ссылку `structure_bundle: {path, sha256}` относительно архива. Для структуры
locator — `$.data`; для текста — `$.redtext` или `$.doctext`.
Разрешение `processing-permission/1` должно явно охватывать оба SHA-256.
Остальные поля статуса, блокеров, дат и идентичности сохраняют прежний смысл.
Старые входы не мигрируются автоматически.

Перед производными записями компилятор проверяет хеши, принадлежность активов
source item, исходное свидетельство редакции, селекторы транспортных запросов
и ответов. Для ips также сверяются `docid/baseid/rdk` внутри текстового ответа.
Идентичность акта подтверждается по заголовку и реквизитам исходного текста.

```powershell
python -m legal_rag.corpus compile `
  --input <путь-к-corpus-input-2.json> `
  --target-date 2026-10-15 `
  --output-dir <новый-каталог-результатов>
```

Новый результат — `legal-ast/2`, профиль `official-structure/2`:

- исходные структурные узлы имеют указатель `/data/N` на JSON и диапазон HTML;
- родители проверяются по уровню, префиксу идентификатора и вложенности диапазонов;
- номера сверяются с HTML, включая надстрочные индексы и составные номера;
- собственные текстовые блоки владеют токенами ровно один раз;
- таблицы, строки, ячейки и изображения сохраняют исходные диапазоны;
- диапазоны символов и UTF-8 относятся к декодированной HTML-строке,
  а не к байтам внешнего JSON или страницам PDF.

Цитаты поправок вложены в исходный изменяющий пункт через `quote`. Например,
статьи 9.16 и 23.71 внутри статьи 37 №261-ФЗ не становятся собственными статьями
№261-ФЗ. Для цитат сохраняются границы в `numbering_text` и исходный абзац.
Если граница проходит внутри абзаца со внешним текстом, сохраняется блокер:
точное разделение такого абзаца пока не квалифицировано.

Формы получают `form_section`, `list` и `list_item` с `content_context=form`.
Нумерованные строки таблиц представлены `table_row_item`; остальные ячейки
остаются у своей строки. Это сохраняет структуру формы/таблицы без утверждения,
что каждый её элемент является самостоятельной нормой закона.

Для редакторских примечаний структурное нахождение внутри диапазона отделено
от юридической области действия. Отдельный абзац примечания остаётся на уровне
документа с `scope_status=unresolved`; соседство не считается доказательством.
Растровые формулы сохраняются как изображения без выдуманной транскрипции.

## Оставшиеся ограничения

Повторная [классификация этих случаев](M1_03A_STRUCTURE_GAP_TRIAGE_2026-10-15.md)
показала, что не все предупреждения означают потерянную структурную единицу:
два пункта 6² требуют собственных узлов, а список формы и встроенные цитаты
можно сохранять цельными абзацами в правильных контейнерах. Это предложение
о гранулярности; перечисленные ниже результаты запуска и блокеры кода сохранены.

У №354 HTML содержит два пропущенных JSON номера 6²: `p2382` и `p19446`.
Они сохранены как `unresolved_block`. Нельзя автоматически объявить их детьми
предыдущего 6¹ только потому, что так ограничен исходный JSON-диапазон.

У №354, №261-ФЗ и №410 остаётся `mixed_paragraph_amendment_quote_boundary`:
кавычка открывается/закрывается внутри абзаца, содержащего также внешний текст.
Цитата и весь исходный текст сохраняются, но такой scope блокирует структурную
готовность. Inline-якоря внутри абзацев отклоняются; несколько маркеров через
`br` остаются неразрешёнными вместо потери вложенной нормы.
У №47 обнаружен именно такой дополнительный случай: `p316` содержит
«Приложение к заключению» и пункты а–г в одном абзаце. Он сохранён как
`multiple_provision_markers`; отдельный список а–д в `p350`–`p354` разобран.

Поэтому технический результат 7/7 не означает структурную готовность 7/7.
М1-03А остаётся открытым; новая версия профиля не получила отдельную G13-проверку
на удержанной выборке. Десять юридических допусков редакций М1 остаются отдельной
работой. Неизвестные конструкции не переводятся в утверждённый корпус.
